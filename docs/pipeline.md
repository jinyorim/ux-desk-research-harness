# 파이프라인 (pipeline)

> S1~S5 단계의 입력과 출력, 되돌아가는 지점이다. 범위는 docs/purpose.md, 단계 전환 조건은 docs/gates.md.

## 단계

| 단계 | 하는 일 | 입력 | 출력 |
| --- | --- | --- | --- |
| S1 질문 구체화 (Phase 0) | grilling 방식으로 묻고 사람이 브리프 승인. 세부 작업(M1~G3) 선택과 이유 기록 | 주제 한 문장 | 승인된 브리프, 모듈 선택 기록 |
| S2 조사 | MARKET → COMPETITORS(C5 UI Bowl 포함) → SOLUTION GAP을 엔진별로 실행 | 브리프 | 엔진별 결과 md, 원문 저장본 |
| S3 교차검증과 판정 | 스크립트 판정 후 Jev 더블점검. 확정, 보류, 폐기 분류 | 엔진별 결과, 원문 | 판정표, 실패 목록 |
| S4 인사이트 (항상) + WHY AI, HYPOTHESIS (조건부) | 인사이트는 항상: 표지, KEY FINDINGS, 헤드라인, 조사 한계를 ux-insight 스킬로 쓰고 사람 승인. WHY AI 근거표와 가설 5원칙 체크는 S1에서 "필요"라고 답했을 때만 | 확정 사실 | s4_insights.md(승인), 근거표, 승인된 가설 |
| S5 산출물 생성 | md 원본에서 docx와 html 생성, 다이어그램 포함 | 판정 통과 md | md, docx, html |

## 되돌아가는 지점

- S3 실패(출처 없는 주장, 원문 불일치 수치, 금지 섹션 중 1개 이상) → 실패한 주장이나 섹션만 해당 엔진에 재조사 (S2 부분 재실행). 전체 재실행 아님.
- 재시도는 최대 3회 (검증, 수정, 재시도 구조는 199-biotechnologies/claude-deep-research-skill 참고). 3회 후에도 0이 아니면 해당 주장을 본문에서 빼서 폐기 목록으로 옮기고 사람에게 알린다.
- S1 브리프 미승인 → S2로 넘어가지 않는다.
- S4 인사이트 미승인 → S5로 넘어가지 않는다. 가설을 실행한 경우 가설 미승인도 같다.
- Jev 호출 실패 → 오류로 멈춤 (docs/gates.md).

## 엔진 실행 순서

- 엔진끼리는 병렬 실행.
- 한 엔진 안에서는 MARKET → COMPETITORS → SOLUTION GAP 순차 실행. ChatGPT는 같은 대화창에서 이어서 실행한다. 새 창에서 "앞선 조사를 바탕으로"라고 넣으면 맥락이 없어 엉뚱한 결과가 나온다.
- ChatGPT 앱의 Deep Research는 API가 없어서 Aside 브라우저 에이전트(MCP)로 돌린다. 화면 구조가 바뀌면 깨질 수 있으므로, 실패하면 오류로 기록하고 자동 소스 2개로 게이트 통과 여부만 판정한다 (docs/gates.md G-C). 가져온 결과도 다른 소스와 똑같이 게이트를 통과해야 한다.

## ChatGPT Deep Research가 범위를 되물을 때

- 브리프에 답이 있으면 브리프 내용으로 자동 답변.
- 브리프에 없는 질문이면 멈추고 사람 호출.

> S4 인사이트는 주제와 상관없이 항상 실행한다. 근거 docs/research-practice.md.

## 교차 검사

- 단계가 끝날 때마다 다른 에이전트가 검사하고, 통과(종료 코드 0)해야 다음 단계로 간다. 누가 무엇을 어떻게 검사하는지, 기록 형식, 되돌리기 규칙은 docs/review.md.
- S3 판정 뒤에는 다른 모델 감사(audit.py), S5 뒤에는 judge의 보고서 사실 검사(run.py --target s5)와 감사, analyst의 승인본 대조가 붙는다.
