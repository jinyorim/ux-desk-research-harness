# 게이트 (gates)

> 단계를 넘어갈 때 통과해야 하는 조건이다. 수치는 이 문서가 아니라 `harness/rules.yaml`에만 둔다. 이 문서는 조건의 의미와 출처를 적는다.

## 판정 도구 Jev

Jev(`typesafe/jev-1.13`)는 문장을 생성하지 않고 정해 둔 선택지 안에서 답과 확률만 돌려주는 판정 전용 모델이다. 질문 형식은 Choice(보기 중 선택), Score(루브릭 점수), Noul(예/아니오 확률 0~1) 세 가지다. 웹 검색을 스스로 하지 않으므로 조사 엔진이 아니라 게이트의 더블점검용으로만 쓴다.

- OpenRouter를 거쳐 호출한다(`harness/engines.yaml` judge.jev). 키는 `.env`에만 둔다.
- judge 에이전트만 `harness/judge/jev.py`로 호출한다. 조사 에이전트가 호출하면 자기 결과를 자기가 채점하게 된다.
- 원문은 하네스가 먼저 받아 저장하고(Exa contents), 그 본문과 주장을 함께 넘긴다.
- 주장은 한 문장에 사실 하나로 쪼개서 보낸다. Jev는 여러 단계 추론에 약하다.
- 범위 밖 답을 못 낸다는 것이 틀리지 않는다는 뜻은 아니다. 그래서 단독 판정자로 쓰지 않고, 다른 모델이 표본을 다시 판정해 감사한다(docs/review.md).

## 판정 순서

1. 스크립트 항목이 하나라도 실패하면 바로 실패. Jev는 호출하지 않는다.
2. 스크립트를 통과한 주장만 Jev에 보낸다. 상한 이상 통과, 하한 미만 실패.
3. 상한과 하한 사이는 보류 (완료를 막지 않고 보고서에 표기, docs/purpose.md).
4. Jev 호출 실패(접근 중단, 한도 초과)는 오류로 멈춘다. Jev를 건너뛰고 통과시키지 않는다.

실패 시: 해당 주장이나 섹션만 재조사, 최대 3회, 이후 폐기로 옮기고 사람에게 알림 (docs/pipeline.md).

체크 항목마다 스크립트와 Jev 가운데 누가 맡는지는 docs/research-rules.md 7번에 있다.

## G-A. 어기면 안 되는 것 게이트 (docs/story-service.md)

| 어기면 안 되는 것 | 조건 (실패 = 다시 돌림) | 담당 |
| --- | --- | --- |
| 브리프 범위 안에서만 | 브리프의 지역, 기간 밖을 다루는 주장 0개 | Jev(Choice) + 스크립트(날짜) |
| 수치와 주장에 원문 확인된 출처 | 출처 번호 없는 주장 문장 0개 / 접속 실패 URL 0개 / 원문에 없는 숫자나 인용 0개 | 스크립트 |
| 제안, 제언 섹션 금지 | 금지 제목 목록에 걸린 섹션 0개 (제목만 검사) | 스크립트 |
| 다른 업종, 다른 시점 수치 금지 | 대상 도메인 불일치 주장 0개 / 기준일이 허용 기간을 넘었는데 "과거 자료" 표기 없는 수치 0개 | Jev(Choice) + 스크립트 |

- 금지 제목 목록은 "전략적 시사점", "제언"에서 시작해, 1차 딥리서치에서 실제로 나온 오류 사례로 보강했다.

### G-A 보강

- URL 없는 1차 출처: 사람이 직접 관찰한 기록(s2_sources/observations/, 일시와 방법과 캡처 경로)을 원문으로 인정. 참고자료에 `observation: <경로>`로 적는다.
- 기사 날짜를 본문이 아니라 게시일 메타데이터에만 둔 경우, 연월일 숫자는 메타데이터와 대조해 인정.
- "없다" 주장은 Jev 대신 원문 문자열 검사: 해당 낱말이 원문에 있으면 실패, 없으면 보류 (rules.yaml absence). 원문이 직접 "없다"고 적은 경우는 일반 주장으로 Jev.
- S5 보고서에도 적용 (run.py --target s5): 인용 블록과 HYPOTHESIS는 제외, 출처 없는 숫자는 실패, 숫자 없는 출처 없는 문장은 경고, 교차검증 섹션의 판정 건수는 내부 기록 경고.

## G-B. 출처 구성 게이트

출처 구성 수치는 daymade/claude-code-skills의 deep-research 스킬에서 아이디어만 가져왔다 (docs/skills-inventory.md).

| 조건 | 처리 |
| --- | --- |
| 공식 출처(A급) 비율 하한 이상 | 미달 시 실패 → 재조사 |
| 서로 다른 도메인 수 하한 이상 | 미달 시 실패 → 재조사 |
| 한 출처 비중 상한 이하 | 초과 시 실패 → 재조사 |
| 반론 검토 문제 수 | 경고만 (M5 반대 근거와 역할 중복) |

## G-C. 소스 게이트

- 자동 소스(API로 부르는 엔진) 성공 수가 하한 이상. 서로 다른 엔진 두 개 이상의 결과가 있어야 교차검증을 할 수 있다. 브라우저로 돌리는 ChatGPT(Aside) 실패는 오류로 기록하되 이 게이트는 자동 소스로만 판정.

## G-D. UI Bowl 게이트 (C5를 실행한 경우만)

UI Bowl은 출시된 앱과 웹 화면을 모은 읽기 전용 레퍼런스 DB다. 경쟁사와 같은 업종의 비슷한 서비스 화면을 MCP로 찾아 레퍼런스로 모은다.

- 레퍼런스 수 하한 이상 (경쟁사 프로필마다 1개 이상)
- `ui_url` 없는 레퍼런스 0개
- 조회일 없는 MAU, 순위 0개
- 산출물 속 스크린샷 이미지 0개 (화면 설명과 `ui_url` 링크만 넣는다. 스크린샷은 이용약관을 확인하기 전에는 넣지 않는다)
- 화면 설명은 돌려받은 화면 이미지를 직접 보고 쓴다. UI 개선안이나 화면 디자인 제안은 쓰지 않는다.

## G-E. 산출물 게이트 (docs/outputs.md)

- 허용 색(rules.yaml visual) 밖 색 0개
- 단계별 다이어그램 1개 이상, 추가 다이어그램 상한 이하
- 확정 판정이 아닌 사실에서 나온 다이어그램 수치 0개
- 외부 리소스 로드 0개
- 모바일 폭에서 가로 스크롤 0

## G-F. 한국어 문장 게이트 (docs/korean-writing.md)

- 대상: S4 `s4_insights.md`, S5 `s5_report.md`. 도구: `harness/judge/check_korean.py` (Kiwi 형태소 분석). 수치는 rules.yaml korean.
- 실패: 가운뎃점(·), em dash(—), en dash(–, 영문과 숫자 범위 제외) 1개 이상 / 거친 표현 / S1 번역투 1개 이상 / S2 패턴 한 문서 3회 이상.
- 경고(완료를 막지 않음): 한 문장 은/는 3개 이상, 명사 앞 관형절 서술어 3개 이상, 흐린 말, 칸별 길이 초과, 연결어미 뒤 쉼표 10% 초과.
- html은 G-E check_html.py가 화면 글자의 금지 문장부호를 다시 센다.

## G-M. 세부 작업 표 게이트 (.claude/skills/market-modules)

- 대상: S2 리포트의 세부 작업 표 (PESTEL, 경쟁사 프로필과 SWOT, 포지셔닝 맵, 시장 규모, 테마). 도구: `harness/judge/check_modules.py`. 수치는 rules.yaml modules.
- 실패: PESTEL 행 누락, 사실 칸 출처 없음, 해석 칸 숫자, SWOT 칸 출처 없음이나 제언 표현, 포지셔닝 축 정의 없음이나 값 범위 밖이나 근거 출처 없음이나 경쟁사 4개 미만, 시장 규모 계산 불일치, 인용 125자 초과.
- 칸 내용의 진위는 G-A와 같은 S3 흐름(스크립트, Jev, 감사)으로 칸 단위 판정. 판정을 통과한 칸만 S4, S5에서 쓴다.

## 사람 승인 지점

1. S1 브리프 승인 (없으면 S2 진행 불가)
2. S4 가설 승인 (S1에서 필요하다고 답한 경우)
3. 재시도 3회 실패 알림
4. 완료 후 보류 항목 확인 (완료를 막지 않음)
