## 0. 신뢰성 프로토콜 (모든 항목보다 우선 적용)

**0-1. 정량 수치는 원문을 직접 연 뒤에만 사용한다.** 시장 규모, 이용자 수, 성장률, 비율, 전환율 같은 숫자는 그 숫자가 인용한 링크 안에 실제로 있는지 다시 확인한 뒤에만 쓴다. 2차 기사가 인용한 숫자라면 원본 보고서나 발표까지 추적한다. 원문에서 확인할 수 없으면 "확인 불가"라고 표시하거나 문장에서 뺀다. 추정으로 채우지 않는다.

**0-2. 업종이나 도메인이 다르면 효과를 옮겨 쓰지 않는다.** 다른 업종에서 검증된 기능, 효과, 수치를 {{주제}} 시장에 적용된 것처럼 쓰지 않는다. 쓸 때는 "이 수치는 OO 업종 기준이며, {{주제}} 적용 사례는 따로 확인되지 않았다"라고 밝힌다.

**0-3. 인용 번호는 한 문장, 한 수치에만 붙인다.** 인용 번호를 문단 전체나 서로 다른 주장 여러 개에 걸쳐 다시 쓰지 않는다. 한 문장에 숫자나 고유한 주장이 여럿이면 출처도 각각 붙인다.

**0-4. 정량 근거 없는 방향 단정을 금지한다.** "압도적으로", "급격히", "폭발적으로 증가하고 있다", "~하는 추세다" 같은 표현은 수치와 출처가 함께 있을 때만 쓴다. 수치가 없으면 "실제 서비스와 사례에서 반복해서 관찰되나, 비중이나 증가 속도를 뒷받침하는 공개 자료는 확인되지 않았다"처럼 쓴다.

**0-5. 솔루션과 제안 문장을 쓰지 않는다.** "제안한다", "~해야 한다", "전략은", "기능을 도입해야 한다", "~로 차별화해야 한다" 같은 문장을 쓰지 않는다. 결과 구조(아래 A~L)에도 "전략적 시사점", "제언" 섹션을 두지 않는다. 다 쓴 뒤 이런 표현이 남았는지 검색해 사실 서술로 바꾸거나 지운다.

**0-6. 제출 전에 출처를 다시 연다.** 본문에 쓴 모든 출처 링크를 다시 열어, 인용한 문장이나 수치가 그 페이지 안에 있는지 확인한다. 없으면 문장을 지우거나 "이 자료에는 해당 내용이 없어 확인 불가"라고 표시한다.

**0-7. 자사 발표 수치는 출처 성격을 밝힌다.** 기업 보도자료나 자사 블로그의 자사 성과 수치는 "자사 발표 기준"이라고 쓰고, 독립된 제3자 조사나 통계와 구분한다.

## 0.5 범위 정의

**{{주제}}의 범위**: {{세부 유형}}을 모두 포함한다. 유형 사이에 선택 기준이나 이용 방식이 다르게 나타나는지도 함께 본다.

**지역 범위**: {{지역}}을 중심으로 하고, 다른 지역 사례가 확인되면 보조 사례로 넣는다. 특정 지역에 사례가 몰릴 수 있다는 점을 결과에 밝힌다.

**국가 범위**: {{국가}}로 한정한다. 해외에 본사가 있는 기업이라도 {{국가}}에서 실제로 서비스되면 포함한다. 해외 시장 트렌드, 해외 전용 서비스, 해외 이용자 통계는 비교 자료로 쓰지 않는다. 기술 사례(10번)에서도 {{국가}} 사례를 찾지 못하면 "국내 적용 사례를 찾지 못했다"라고 쓰고 해외 사례로 대신하지 않는다.

**기간**: 시장 동향, 이용자 통계, 기업 사례, 기술 사례는 {{기간}} 자료를 우선한다. 원론적인 개념 문헌은 발행 연도와 상관없이 인용할 수 있다.

**이미지 예외**: 출처는 확인되지만 이미지를 확보하지 못한 사례는 본문에서 빼지 않는다. 텍스트 근거로 남기고 시각자료 항목에만 "이미지 확인 불가"라고 쓴다.

**실행 방식**: 두 개 이상의 딥리서치 엔진에 같은 브리프를 넣어 결과를 받고, 아래 교차검증 표로 일치하는 지점과 어긋나는 지점을 나눈다.

# 조사 원칙

**실제로 존재하는 기업, 서비스, 플랫폼, 프로젝트, 연구 사례**만 쓴다. 가상의 사례, 존재를 확인할 수 없는 사례, 출처가 불명확한 사례를 만들지 않는다.

사례마다 다음 가운데 하나로 존재를 확인한다: 공식 홈페이지, 공식 App Store 또는 Google Play 페이지, 공식 보도자료, 정부와 공공기관 자료, 학술 논문, 신뢰할 수 있는 언론 기사, 실제 서비스 페이지, 공식 SNS나 블로그. 확인되지 않으면 주요 사례에서 뺀다.

AI, 개인화, 위치 기반 추천 같은 기능은 **실제로 제공 중인 기능**인지, 계획이나 마케팅 문구인지 구분한다.

# 1. {{주제}} 시장은 최근 어떻게 바뀌고 있는가?

{{주제}}와 인접 시장에서 나타나는 주요 변화를 조사한다. 검증할 변화 가설을 여기에 적는다.

* {{변화 가설 1}}
* {{변화 가설 2}}
* {{변화 가설 3}}

변화마다 ① 기존 방식 ② 최근 변화 ③ 관찰되는 사용자 행동 변화 ④ 실제 사례 ⑤ {{주제}} 시장 이해에 주는 의미, 다섯 가지 구조로 쓴다. 한 자료에 기대지 말고 서로 다른 자료로 교차 확인한다.

# 2. {{대상 고객}}은 {{주제}}를 어떻게 발견하고 탐색하는가?

처음 알게 되고 후보를 찾는 실제 경로를 조사한다. 검색, 지도, SNS, 후기 콘텐츠, 전문 플랫폼({{대표 경쟁 서비스}} 등), 공급자 자체 채널, 지인 추천, 조사 중 새로 발견되는 채널을 포함한다.

한 플랫폼에서 탐색과 결제를 끝내는지, 여러 채널을 오가며 결정하는지 조사한다. 채널별 비중을 뒷받침할 대표 표본 자료가 없으면 없다고 쓰고 구조적 근거(플랫폼 사이 연동 여부 등)로 대신한다. 후기 하나를 시장 전체 행동으로 넓히지 않는다.

# 3. {{대상 고객}}은 무엇을 기준으로 고르는가?

가격, 위치, 시간, 품질 신호, 후기, 사진, 동행자, 이용 목적 등 조사에서 확인되는 기준을 정리한다. 나열에 그치지 말고 실제 선택 상황에서 무엇을 비교하고 무엇이 결정을 바꾸는지 분석한다. **정량 자료 없이 어느 기준이 더 우세하다고 결론 내리지 않는다.**

# 4. 이용 목적은 어떻게 나뉘는가?

예상되는 목적을 정답으로 두지 말고 실제 자료로 검증해 유형으로 나눈다. 목적마다 탐색 방식과 선택 기준이 달라지는지 본다. 이용자를 하나의 집단으로 가정하지 않는다.

# 5. 함께 이용하는 사람은 선택에 어떤 영향을 주는가?

혼자, 친구, 연인, 가족, 동료 등 동행자별 차이를 조사한다. 링크 공유, 일정 조율, 한 사람이 찾아 제안하는 행동, 의견 불일치가 실제로 나타나는지 확인한다. {{주제}} 전용 자료가 없으면 인접 시장 자료를 쓰되 "{{주제}} 전용 자료가 아니며 인접 시장의 신호"라고 밝힌다.

# 6. {{주제}}와 장소, 맥락의 관계 (해당할 때)

오프라인 장소가 중요한 주제라면, 사용자가 서비스 자체 외에 지역, 접근성, 주변 활동, 하루 일정을 함께 고려하는지 조사한다. 서비스부터 고르는 행동과 장소나 상황부터 정하는 행동이 각각 존재하는지 확인하되, **어느 쪽이 더 많은지는 정량 자료 없이 단정하지 않는다.** 비중 질문은 K 항목으로 넘긴다.

# 7. 실제 이용 과정은 어떻게 구성되는가?

실제 운영 중인 {{공급자}}와 서비스 페이지를 조사해 대표적인 이용 절차를 정리한다. {{세부 유형}}마다 사례를 두 개 이상 찾는다. 여러 사례에 반복되는 공통 절차를 찾고, 이용 전에 알아야 하는 정보와 현장에서 안내받아도 되는 정보를 구분할 근거가 있는지 본다.

# 8. 이용 이후 행동은 어떻게 이어지는가?

기록, 후기 작성, 공유, 재이용, 다른 서비스 탐색, 정기 이용으로의 전환, 아무 행동 없음을 조사한다. 한 번으로 끝나는 경우와 반복 이용으로 이어지는 경우를 구분한다. 자료가 부족하면 부족하다고 쓰고, 후기에서 보이는 초기 신호와 검증된 시장 현상을 나눈다.

# 9. {{공급자}} 관점에서 시장은 어떻게 짜여 있는가?

고객 확보, 플랫폼 활용, 수수료, 예약과 일정 관리, 취소, 반복 문의, 후기 관리, 재방문 유도, 자체 브랜드 구축을 조사한다. 운영자 인터뷰, 기사, 판매자 가이드, 공식 자료를 쓴다. **수수료처럼 시간에 민감한 수치는 확인 연도를 쓰고, 2년 넘은 자료는 "과거 자료이며 현재 유지 여부는 확인되지 않음"이라고 표시한다.** 공급자 문제를 풀 신규 서비스를 제안하지 않는다.

# 10. 최근 기술은 {{주제}} 탐색과 이용을 어떻게 바꾸고 있는가?

위치 기반 추천, 지도 탐색, 자연어 검색, 개인화 추천, 생성형 AI, 대화형 탐색, 이미지 검색, 일정 추천, 예약 자동화, 리뷰 요약의 실제 적용 사례를 조사한다. **{{국가}} 사례로 한정한다.** 직접 적용 사례가 부족하면 인접 도메인까지 넓히되, **쓸 때마다 "이 사례는 OO 도메인이며 {{주제}} 직접 적용 사례가 아니다"라고 밝힌다.** 기존 행동 → 적용 기술 → 바뀐 경험 순서로 분석한다.

# 11. 경쟁 구도

전문 플랫폼, 인접 플랫폼, 공급자 직접 채널 등 유형별로 실제 대표 서비스를 조사한다. {{대표 경쟁 서비스}}를 포함하고 조사에서 확인되는 서비스를 더한다. 서비스마다 다음 항목으로 정리한다.

| 항목 | 내용 |
|---|---|
| Service / Company | 실제 서비스와 기업 이름 |
| Current Status | 현재 운영 여부 (종료됐으면 시점) |
| Target User | 주요 사용자 |
| Core Offering | 제공하는 경험 |
| Discovery | 발견 방식 |
| Personalization | 개인화 여부 (실제 출시 기능만) |
| Booking / Payment | 예약과 결제 기능 |
| Fee | 수치와 **확인 연도**, 2년 넘으면 과거 자료로 표시 |
| Reviews / Content | 후기와 콘텐츠 |
| After Use | 이용 이후 지원 |
| Supplier Support | 공급자 지원 |
| Evidence Grade | A, B, C (항목마다) |
| Source URL | 원문 링크 (제출 전 재확인) |

# 출처와 근거 등급

모든 핵심 주장과 사례에 출처를 단다. 형식: **[출처명 / 기관명 / 발행일 또는 확인 연도 / 원문 링크]**. 링크가 없는 사례는 쓰지 않는다.

문장 끝이나 표 칸에 등급 [A], [B], [C]를 직접 붙인다.

* **A, 1차 근거**: 기업 공식 자료, 정부 통계, 학술 논문, 공식 서비스 페이지
* **B, 신뢰할 수 있는 2차 근거**: 주요 언론, 전문 산업 매체, 시장 리포트
* **C, 사용자 생성 근거**: 앱 리뷰, 블로그, 커뮤니티, SNS

C급 자료는 사용자 행동을 발견하는 데만 쓰고 시장 전체의 사실처럼 쓰지 않는다.

주요 사례는 가능하면 실제 사진이나 화면 자료를 찾는다. 생성 이미지는 쓰지 않는다. 우선순위: 공식 홈페이지 화면 → 공식 미디어 키트 → 공식 블로그와 보도자료 → 스토어 공식 스크린샷 → 공식 영상과 SNS → 언론 기사 사진. 저작권이 불분명한 이미지는 뺀다. 이미지마다 설명, 서비스 이름, 이미지 출처, 원문 URL, 넣은 이유를 적는다.

# 제출 전 검증

1. 본문의 모든 기업, 서비스, 사례가 실제로 존재하고 지금 운영 중이며 기능이 실제 출시됐는지 다시 확인한다.
2. **본문의 모든 출처 링크를 다시 열어 인용한 문장이나 수치가 그 페이지에 있는지 확인한다.** 없으면 지우거나 "확인 필요"로 표시한다.
3. "제안한다", "~해야 한다", "전략은" 같은 솔루션 문장이 남았는지 검색해 지우거나 사실 서술로 바꾼다.
4. 정량 근거 없는 단정 표현이 남았는지 확인해 지운다.
5. 인접 도메인 사례를 {{주제}} 시장 사실처럼 쓴 문장이 있으면 도메인 구분 문구를 넣는다.
6. 다른 기업 사례를 잘못 붙였을 가능성을 다시 확인한다.

확인되지 않은 내용을 추측으로 채우지 않는다. 자료가 없으면 "공개적으로 확인 가능한 근거를 찾지 못했다"라고 쓴다.

# 이 조사의 목적

신규 서비스 아이디어를 만드는 것이 아니라 현재 시장과 실제 사용자 행동을 정확히 이해하는 것이다. "이런 서비스를 만들면 좋다", "이런 기능을 넣어야 한다"처럼 솔루션으로 결론 내리지 않는다. 시장 변화 → 사용자 행동 → 기업과 서비스 사례 → 근거 순서로 분석하고, 모든 주요 사례에 출처 이름과 원문 링크를 단다.
