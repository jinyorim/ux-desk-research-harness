# 목적 (purpose)

> 하네스가 누구를 위해 어디까지 하는지, 언제 끝난 것으로 보는지 정한다. 근거: docs/prd.md, docs/story-service.md.

## 하네스 사용자
주제를 바꿔 가며 데스크리서치를 반복하는 디자이너 1명 (docs/prd.md 2번).

## 범위
Phase 0(질문 구체화) + Phase 1(데스크리서치)까지. 정량 조사(서베이 설계, 합성 데이터, 자연어 분석)와 정성 조사(인터뷰 설계, 진행, 분석)는 범위 밖이다. 주제는 AI 서비스에 한정하지 않는다.

| Phase | 작업 | 담당 |
| --- | --- | --- |
| 0. 질문 구체화 (S1) | 주제 한 문장에서 리서치 질문과 조사 범위 만들기 | 하네스가 묻고, 사람이 답하고 브리프를 승인 |
| 1. 데스크리서치 (S2~S5) | MARKET: 이 도메인에서 지금 중요한 변화 | 하네스 (소스 2개 이상) |
| | COMPETITORS: 기존 서비스의 해결 수준과 Gap(잘 해결됨, 일부만 제공, 미해결), 유사 서비스 UI 레퍼런스 | 하네스 |
| | SOLUTION GAP: 반복 의견을 테마로 묶고 테마마다 관찰된 행동, 불편, 지금의 해결 방법, 남은 마찰, 근거를 정리. Unmet Needs 5~8개 | 하네스 |
| | INSIGHT 종합 | 하네스 초안, 사람 확정 |
| | WHY AI: 문제와 AI 강점 6분류 대응. S1에서 "AI를 쓰는 서비스"라고 답한 경우만 | 사람. 하네스는 근거표만 준비 |
| | HYPOTHESIS: 가설 3~5개, 작성 5원칙. S1에서 가설이 필요하다고 답한 경우만 | 사람. 하네스는 5원칙 체크만 |

MARKET, COMPETITORS, SOLUTION GAP 안의 세부 작업(M1~M5, C1~C5, G1~G3)과 실행 조건은 `.claude/skills/market-modules/SKILL.md`에 있다. 주제마다 어떤 세부 작업을 돌릴지는 S1 브리프를 보고 정하고, 그 이유를 `runs/<slug>/s1_modules.md`에 남긴다.

## 실행할 때마다 달라지는 것 (입력)
1. 주제 한 문장
2. S1 질문에 사람이 한 답 (대상, 기간, 인사이트나 간략한 의견, AI 서비스 여부, 가설 필요 여부)
3. 하네스가 고른 세부 작업 M1~M5, C1~C5, G1~G3과 그 이유
4. 엔진별 결과
5. 실행 날짜 (기준일 판정의 기준)

이 다섯 가지 외의 규칙, 엔진 설정, 시각 규칙은 실행마다 바뀌지 않는다.

## 완료 기준
사람이 승인한 브리프가 있고, 자동 소스 2개 이상이 MARKET, COMPETITORS, SOLUTION GAP을 마쳤으며, 출처 없는 주장 0개, 원문 불일치 수치 0개, 금지 섹션 0개인 md를 원본으로 docx와 html이 `runs/<slug>/`에 생성되면 완료.

- 출처 없는 주장, 원문 불일치 수치, 금지 섹션이 1개라도 있으면 완료가 아니며 다시 돌린다. 세 값이 모두 0이 된 뒤에 완료로 본다.
- 보류 항목은 완료를 막지 않는다. 완료 후 보고서에 보류로 표기한다.
- WHY AI와 HYPOTHESIS는 S1에서 "필요"라고 답한 경우에만 완료 조건에 들어가고, 이때 사람 승인 1회가 추가된다.
